# Story 1.7: 登录访问门禁

Status: review

## Story

As a 系统使用者，
I want to 在进入航天任务调度工具前使用账号和密码登录，
so that 系统页面不会在未验证身份时直接开放访问。

## Acceptance Criteria

### AC1 - 登录页面与默认凭据提示

1. 系统提供独立的 `/login` 登录页面，首次访问或未登录时不显示业务顶栏、规划导航与业务页内容。
2. 登录页包含账号、密码、显示/隐藏密码和登录操作，支持按 Enter 提交。
3. 页面明确提示默认账号 `admin` 和默认密码 `123456`，但输入框不自动填充密码。
4. 账号或密码错误时停留在登录页并显示明确错误；成功后进入原目标地址，没有目标地址时进入工作台。
5. 登录页面在常见桌面与移动宽度下不溢出、不遮挡，视觉风格与现有项目一致。

### AC2 - 路由访问控制与会话状态

1. 除 `/login` 外的全部前端路由默认要求登录；直接输入任意业务 URL 时必须跳转登录页。
2. 跳转登录页时保留原目标路径，登录成功后返回原目标路径。
3. 登录状态保存在 `sessionStorage`，同一标签页刷新后保持，关闭会话后不长期保留。
4. 已登录用户访问 `/login` 时自动返回工作台。
5. 登录成功后的重定向仅接受站内绝对路径，不允许协议相对地址或再次跳转登录页。

### AC3 - 退出登录与应用框架

1. 登录后的顶栏提供含可访问名称和提示的退出登录图标按钮。
2. 点击退出登录后清除会话并返回登录页，后退或直接访问业务路由仍会被拦截。
3. 登录页不显示下载示例、导航栏和业务页脚；业务页面的现有布局和功能保持不变。

### AC4 - 测试、文档与安全边界

1. 单元测试覆盖正确/错误凭据、会话保存与清除、未登录拦截、原地址返回和重定向安全校验。
2. 组件测试覆盖默认凭据提示、密码显隐、错误反馈和成功登录。
3. README 更新当前能力与限制，明确该功能是前端原型门禁，默认凭据公开，不等同于服务端认证或生产级安全控制。
4. 完成前端 Vitest、生产构建、定向 ESLint 和 `git diff --check`。

## Dev Notes

- 当前后端没有用户、会话、令牌或数据库模型；本 Story 按用户指定的公开默认凭据实现前端原型门禁，不伪装为安全认证。
- 认证状态只使用独立的 `sessionStorage` key，不接入现有规划包、Pinia 业务 Store 或 localStorage 历史文档。
- 路由采用“默认保护、登录页显式公开”的策略，避免新增业务路由时忘记配置保护。
- 复用 Vue Router 4、Ant Design Vue 和现有主题变量，不新增依赖。
- 保留用户原目标地址，但只接受以单个 `/` 开头的站内路径，拒绝 `//host` 和 `/login`。
- README 必须同步修改“系统当前没有用户账号”的既有表述，改为准确描述前端原型门禁与安全边界。
